1 · System context

The product promise in one picture. A person writes a sentence describing a character; a voice that has never existed comes back, and it stays that same voice across every line of a script.

2 · The two-tower thesis

Why this architecture at all, and the one experiment that had to pass before anything else was worth building.

3 · The mint pipeline, in full

Every box here is real code in alaap/mapper.py and alaap/service.py. This is the path a description takes to become a stored identity.

4 · The render pipeline

Identity is fixed; performance is per line and never enters the identity record. That separation is invariant I5.

5 · The gate stack

Five gates, four of them calibrated on a corpus rather than chosen. Each answers a different question, and the project spent nineteen experiments not noticing that none of them asked about naturalness.

6 · Reversibility — the property that makes captions checkable

Most caption datasets ask an audio model to describe a voice. You cannot verify that. Alaap measures first and writes prose from the measurements, so a claim can be checked by re-measuring the render.

7 · Speaker-space geometry

You cannot treat a speaker embedding space as isotropic. This is invariant I1, and ignoring it collapses every identity onto one voice.

8 · The attribute taxonomy

Seventeen things are measured. Only three describe a voice, and working out which three took five experiments.

9 · Two backends, one interface

English and Indic differ in model, codec, sample rate and vector width. The renderer adapter has carried an Indic implementation since S6 — because if the interface cannot express Indic, the interface is wrong (ADR-003, guard 2).

10 · Inside MioCodec — the content / identity split

This split is what makes the Indic experiments cheap. It is also where the project's most expensive bug lived.

11 · The Direction channel

Per-line performance on a backend with no instruct input. Three mechanisms were tried; one works, one is bounded, one is inert.

12 · Module map

Sixteen modules in alaap/. Arrows are imports, so they point from a module to the one it depends on. Nothing below the line touches a model.

13 · Experiment lineage

Thirty-five experiments. What matters is not the count but which ones changed a decision — and how many later ones exist only to check an earlier one.

14 · Plan stages, with real status

The same picture as RESEARCH/GRAND-PLAN.md §3, with every box coloured by what is actually committed.
